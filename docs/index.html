The problem

Every other MCP browser ships a browser binary.

Playwright MCP? ~250MB. Puppeteer MCP? ~400MB. bwb speaks the Chrome DevTools Protocol directly — over one thin CDP client, no Playwright, no Puppeteer, no bundled browser. It drives the Chrome you already have. No downloads. No binary mismatches.

Static-first · v4

The browser starts only when it must.

Every request descends a ladder. Most pages never leave the first rung — so a plain README fetch never wakes Chromium at all.

1

Fetch the page directly

One HTTP GET. No browser process, no CDP socket, no renderer.

cost · ~0 MB
2

Extract the text in-process

Readability + linkedom pull the content out. mode: "static" returns in milliseconds.

cost · ~0 MB Chromium
3

Escalate — only if JS demands it

Scripts, hydration, or interaction required? Chromium boots and the URL is carried across. mode: "browser", with the reason.

cost · on demand
4

Dead URLs never spawn anything

A 404 errors on the static rung. No browser process is ever created for it.

cost · zero

Measured on-device: a single YouTube tab costs 746 MB of Chromium tree. That is why the ladder exists.

Vigilance & survival

Built to be killed — and come back.

Android's out-of-memory killer ate whole Termux sessions. So bwb watches itself: it sheds load before the OS does, journals everything, and tells your agent exactly what it did.

[bwb resources] on every response

MCP + Chromium MB, tab count, ok / watch / critical. The footer is the contract — read it before spawning more work.

Hibernation, then honesty

On critical pressure bwb hibernates tabs itself, journals them, and tears down only after two consecutive critical samples — never mid-watch.

Tabs resurrect from the journal

Kills become resume points, not disasters. The journal stores origin + path only — OAuth callbacks and reset tokens never land on disk.

Survival profile --lean

Auto-on Termux: capped renderers, 3-tab cap, 5-minute mayfly teardown, 256 MB JS heap. Runs on a 1 GB VPS.

Standout tools

The four that actually matter.

browser_act

Natural language interaction — “search for X”, “click the button”. Pure DOM heuristics, no LLM dependency. Scores, measures and scrolls elements instead of guessing; ambiguous labels return candidates; destructive clicks need force:true.

browser_watch

Live console, network, exception and navigation streaming — the only MCP browser that lets your agent listen to a page. Debug SPAs, catch React errors, see the API calls.

browser_diagnose

Lighthouse for your agent: load timings, console errors, broken images, interaction counts and a heuristic health score. Self-diagnosis instead of guessing.

Sessions & screenshots

Login once, agent works for days — cookies persist across restarts (600 on disk). Element-level screenshots: one form, one chart, one card — not the whole page.

Works with anything that speaks MCP: Claude Code, OpenCode, Antigravity CLI, Cline, Continue.dev, Aider, Codex CLI, Cody, Windsurf, Cursor.
